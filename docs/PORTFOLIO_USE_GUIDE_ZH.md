# 作品集使用说明（中国语）

## 先看什么

不要一上来就向HR解释模型。推荐顺序：

1. 打开每个项目的 `outputs/summary.html`，先熟悉“问题—数字—建议”。
2. 阅读项目README中的60秒说明。
3. 面试被追问时，再打开CSV、SQL和Python代码证明技术细节。

## 投递时怎么放

- 职务经历书：在“自己PR/活かせる経験”后放GitHub总链接，只写3个项目名和一句成果。
- GitHub置顶：按 `01 → 02 → 03` 顺序。第一个最能连接你过去的QA/RPA经验。
- LinkedIn/Wantedly：只放总链接，不同时贴大量截图。
- 面试资料：准备3页PDF，每个项目1页，内容来自各项目 `summary.html`。

## 你的统一转职故事

你不是“零经验转行”。你的主线是：

> 我过去通过RPA、QA和业务改善，持续把现场问题转化为可验证、可标准化的流程。现在进一步用SQL、Python和BI，把“自动化处理”升级为“用数据支持判断和改善”。

三个项目分别证明：

- 项目1：能把QA的异常发现和RPA的流程效率经验转化为风险监控。
- 项目2：能用SQL整理跨表数据，并把分析结果转化为营业优先顺序。
- 项目3：能处理金融业务中的解释性、时间顺序和情景分析。

## 不要这样说

- 不要说“模型准确率很高，所以能直接上线”。这些是合成数据。
- 不要把模型结果说成真实银行成果。
- 不要只背AUC。必须解释为什么选择这个KPI、阈值如何影响业务。
- 不要说自己会Power BI就结束。说明你会定义KPI、设计页面和推动使用。

## 上传GitHub前

1. 在自己的Windows电脑上运行 `setup_windows.bat` 和 `run_all_windows.bat`。
2. 确认三个HTML都能打开、日语没有乱码。
3. 将总文件夹名改为简洁英文，例如 `financial-data-analyst-portfolio`。
4. GitHub仓库设为Public，不上传简历、电话、住址等个人信息。
5. README顶部补充你的姓名（英文或日文）和LinkedIn链接即可。
